Quick reference

Run your first check

Mission win: make one trustworthy run and know what evidence it produced.

1. Preview before execution

From the SAT project directory, point the script at a repository. Start with a dry run because project-defined scripts are arbitrary code.

py -3 pre_llm_checks.py --path C:\code\my-repo --dry-run

Read the planned projects and commands. No project commands should execute, and no report is written by a normal dry run.

2. Run the check

py -3 pre_llm_checks.py --path C:\code\my-repo

The four stages are Build, Lint, Tests, and Coverage. Python projects commonly have Build SKIP because there is no compile step; that is not a failure.

Core distinction: FAIL means a command failed. WARN means the tool could not gather some evidence because of setup or configuration. SKIP means a stage did not run.

3. Find the evidence

Look at the terminal table first. Then open pre-llm-report.json. It records project paths, commands, sources, statuses, durations, masked output tails, and log paths. Full logs are under .pre-llm/logs/.

4. Test yourself

Without looking back: If Build fails, what happens to Lint, Tests, and Coverage? What flag still allows Lint to run?

Reveal answer

They are skipped by the build gate. --lint-anyway still runs Lint.

One edge case to remember

If tests run but find no tests, Tests is SKIP with no_tests_found, while Coverage is FAIL. This prevents an empty test suite from looking healthy.
