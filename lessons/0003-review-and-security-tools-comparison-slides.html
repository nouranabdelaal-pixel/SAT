Study slides · 01

What SAT does
and what it does not

Pre-LLM Checks is a local evidence collector. It proves whether a repository's own build, lint, tests, and coverage commands ran and what they reported.

SAT is not an AI reviewer.
It does not inspect code semantically, comment on pull requests, scan dependencies for vulnerabilities, or enforce a coverage threshold.

Sources: SAT README · SAT SPEC

Baseline · 03

Our script: Pre-LLM Checks

Strengths

  • Local Python CLI; no third-party packages.
  • Build → Lint → Tests → Coverage.
  • Uses project-defined commands only.
  • Dry run, timeouts, process-tree cleanup.
  • Masked logs and bounded JSON report.
  • Monorepo discovery and language rulebook.

Not included

  • No semantic code review.
  • No PR/GitHub workflow.
  • No dependency vulnerability scan.
  • No license/compliance inventory.
  • No sandbox or dependency installation.
  • No structured JUnit/SARIF findings yet.

AI review · 04

CodeRabbit

An AI pull-request review and coding-assistance product.

Extra compared with SAT

  • Reviews diffs semantically.
  • Posts review comments and summaries.
  • Suggests fixes and maintainability improvements.
  • Works in hosted PR workflows.
  • Configurable review behavior.

What SAT still does better

  • Runs the repository's actual commands locally.
  • Shows exact command, status, duration, and output.
  • Does not require remote code indexing.
  • Deterministic evidence rather than probabilistic findings.

AI review · 05

Greptile

AI code review with repository-wide context through indexed code.

Extra compared with SAT

  • Understands broader repository context.
  • Reviews pull requests.
  • Answers questions over indexed code.
  • Provides natural-language findings.
  • Integrates with PR providers.

Trade-off

Repository indexing and hosted service access become part of the trust and privacy model. Its review comments do not prove that the project's build, tests, or coverage passed.

AI review · 07

Qodo / Qodo Merge

AI-assisted review and PR workflow automation.

Extra compared with SAT

  • Review agents analyze changes.
  • PR comments, summaries, and suggestions.
  • Configurable review rules and context.
  • CI/PR workflow integrations.

Boundary

Qodo's review output is not the authoritative result of every project-defined command. Security coverage should not be assumed unless a specific documented product/integration provides it.

Can SAT add these capabilities? · 10

Yes, but add layers—not confusion

Discover→Run checks→Parse findings→Security adapters→AI context

Good additions

  • JUnit XML and SARIF parsers.
  • Dependency inventory adapters.
  • Secret scanning with stronger masking.
  • Optional SAST/SCA tool execution.
  • Report fields for findings and severity.
  • CI output formats and PR annotations.

Keep separate or opt-in

  • Dependency installation.
  • Hosted AI review.
  • Repository mutation.
  • Security scanners with network access.
  • Pass/fail policy gates.
